解決する課題

Web3が抱える
「人間」の不在問題

ブロックチェーンはアドレスを区別できますが、その背後に人間がいるかどうかを知ることはできません。 これが多くの問題の根本原因です。

🤖

Sybil攻撃

1人のアクターが無数のウォレットを作成し、ガバナンス投票・エアドロップ・報酬プログラムを不正に独占します。多くのDAOがこの問題で機能不全に陥っています。

🎰

ボットによるNFT・エアドロップ汚染

ミントやエアドロップの大半がボットに奪われ、本物のユーザーは恩恵を受けられません。プロジェクトのトークノミクスも歪められます。

🗳️

ガバナンスの形骸化

トークン保有量だけに依存した投票は、大口保有者やボットファームによって容易に操作されます。「1人1票」の民主主義がWeb3では実現できていません。

🔗

プライバシーとコンプライアンスのジレンマ

KYCで本人確認すれば個人情報が漏洩し、しなければ規制違反になるリスクがあります。この二律背反を解決する手段がありませんでした。

統合ガイド

NEARアプリにWorld ID認証を組み込むまでの実際の流れです。

01

World Developer Portal でアプリを登録

developer.worldcoin.org でNew Actionを作成。app_id と action を取得します。アクションは「vote_dao_proposal_42」のようにユニークな文字列です。

02

フロントエンドで IDKit を組み込む

React / Next.js コンポーネントに World ID ウィジェットを埋め込みます。ユーザーが認証すると ZK Proof が返ってきます。

import { IDKitWidget } from '@worldcoin/idkit'; <IDKitWidget app_id="app_staging_..." action="vote_proposal" signal={nearAccountId} onSuccess={({ proof, merkle_root, nullifier_hash }) => verifyOnNear(proof, merkle_root, nullifier_hash) } />
03

NEAR コントラクトで Proof を検証

Rust で書いたコントラクトが Groth16 検証を実行。Nullifier Hash を保存して二重使用を防ぎます。

// Rust (NEAR SDK) #[near_bindgen] impl Contract { pub fn verify_humanity( &mut self, root: String, nullifier_hash: String, proof: String, ) -> bool { assert!(!self.used_nullifiers.contains(&nullifier_hash), "Already verified"); let valid = groth16_verify(&root, &nullifier_hash, &proof); if valid { self.used_nullifiers.insert(nullifier_hash.clone()); self.verified_humans.insert(env::predecessor_account_id()); } valid } }
04

認証済みアドレスへのアクセス制御

他のコントラクトやメソッドで is_verified_human() を呼び出すだけで、Sybil-resistant なロジックを実装できます。

// ガバナンスコントラクトでの利用例 pub fn cast_vote(&mut self, proposal_id: u64, vote: bool) { let voter = env::predecessor_account_id(); assert!( world_id_contract::is_verified_human(voter.clone()), "World ID verification required" ); // 1人1票を保証した投票処理... }
